# 監査チェックリスト (Audit Checklist)

本ドキュメントは、Agent 4 (Audit Architect) が各エージェントの成果物を監査する際の基準を定義する。

## 1. 対 Agent 1 (Framework Architect) 監査
- [ ] **非機能要件の網羅性**: 認証、ロギング、パフォーマンスの要件が `framework_spec.md` に明確に定義されているか。
- [ ] **セキュリティ基準**: 定義されたセキュリティプロトコル（TLS 1.3, AES-256 等）は、現在の業界標準を満たしているか。
- [ ] **実現可能性**: 提示された要件は、現在の技術スタック (Java 25, Spring Boot 3) で実装可能か。

## 2. 対 Agent 2 (Designer) 監査
- [ ] **API 定義の整合性**: `api_spec.md` の定義は、RESTful の原則に従っているか。
- [ ] **エンティティ設計**: Entity と DTO が明確に分離され、`backend_spec.md` に準拠しているか。
- [ ] **ドキュメント品質**: 日本語の表現は正確で、技術用語の使用は適切か。

## 3. 対 Agent 3 (Developer) 監査
- [ ] **コーディング禁則事項 (Hard Rules)**:
    - [ ] `var` が使用されていないか (完全禁止)。
    - [ ] `@Autowired` によるフィールド注入が行われていないか (コンストラクタ注入必須)。
- [ ] **仕様準拠**:
    - [ ] ページネーションは `LIMIT/OFFSET` で実装されているか。
    - [ ] ログ出力時にマスキングルールが適用されているか。
- [ ] **コード品質**: 命名規則、メソッドの長さ、複雑度は許容範囲内か。

## 4. 対 Agent 5 (Test Engineer) 監査
- [ ] **テストアーキテクチャ**: `@SpringBootTest` を使用せず、Mockito による軽量テストとなっているか。
- [ ] **カバレッジ**: 正常系 (Happy Path) だけでなく、異常系 (Edge Cases) も網羅されているか。
- [ ] **アサーション**: AssertJ を使用し、可読性の高い検証コードになっているか。
