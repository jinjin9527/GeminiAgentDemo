# フレームワーク・非機能要件仕様書 (Framework & Non-Functional Spec)

## 1. 認証・セキュリティ (Authentication & Security)
### 1.1 サーバー間認証
- **プロトコル**: 内部マイクロサービス間の通信には、相互TLS (mTLS) または OAuth2 (Client Credentials Flow) を標準とする。
- **API キー**: 外部パートナーとの通信には、ローテーション可能な API キーを使用し、HTTP ヘッダー `X-API-KEY` で送信すること。

### 1.2 データ保護
- **通信の暗号化**: 全ての HTTP 通信は TLS 1.3 以上を必須とする。
- **保存データの暗号化**: データベース内の機密情報（パスワード、決済情報）は、AES-256 以上の強度で暗号化して保存すること。

## 2. ロギングと監査 (Logging & Audit)
### 2.1 統一ロガー
- **ライブラリ**: SLF4J + Logback を標準とする。`System.out.println` の使用は厳禁。
- **フォーマット**: JSON 形式で出力し、ログ解析基盤（ELK Stack 等）での取り込みを容易にすること。
  - 必須フィールド: `timestamp`, `level`, `traceId`, `spanId`, `serviceName`, `message`

### 2.2 ログマスキング (脱敏) ルール
個人情報保護のため、以下のフィールドはログ出力時に必ずマスキングすること。
- **クレジットカード番号**: 下4桁以外を `*` に置換 (例: `****-****-****-1234`)。
- **メールアドレス**: `@` 前の3文字目以降を `*` に置換 (例: `te**@example.com`)。
- **パスワード**: ログ出力禁止 (完全除外)。

## 3. パフォーマンスと信頼性 (Performance & Reliability)
### 3.1 データベース接続
- **コネクションプール**: HikariCP を使用する。
  - `maximum-pool-size`: デフォルト 10 (負荷試験に基づき調整)。
  - `connection-timeout`: 30秒。

### 3.2 クエリパフォーマンス
- **スロークエリ基準**: 実行時間が **500ms** を超えるクエリは「スロークエリ」と見なし、アラート対象とする。
- **N+1 問題**: MyBatis の `ResultMap` や `JOIN` を適切に使用し、N+1 問題を回避すること。

### 3.3 API レスポンス
- **目標応答時間**: 95パーセンタイル値 (P95) で **200ms** 以内を目指すこと。
