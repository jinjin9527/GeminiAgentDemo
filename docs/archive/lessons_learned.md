# アーキテクチャ上の教訓 (Lessons Learned)

## 1. 暗黙的推論より明示的型宣言 (Explicit over Implicit)
`var` はボイラープレートコードを削減するが、複数人での開発やコードレビューにおいては、明示的な型宣言（例: `List<UserDTO>`）の方が認知負荷を下げ、特に複雑なジェネリクスを扱う際の型推論ミスを防ぐことができる。

## 2. DTO 層の必要性 (Necessity of DTOs)
データベースのエンティティ (Entity) を直接公開すると、内部構造（パスワードフィールドなど）の漏洩や API 契約の不安定化を招く。不変な DTO (Record) 層を導入することで、変換の手間は増えるが、API の安全性と独立した進化能力が得られる。

## 3. 設定もコードである (Configuration as Code)
依存関係管理 (`build.gradle`) やアプリケーション設定 (`application.yaml`) はアーキテクチャの一部であり、単なる運用の詳細ではない。これらが欠けていると「ロジックは正しいが動作しない」コードになる。開発の初期段階から設定もコードと同様に保守すべきである。
